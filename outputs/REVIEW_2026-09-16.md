# Project review - 16 September 2026

This is a historical review, not the current release status. The five issues below were subsequently fixed: family-loading callback and forwarding, the fitting creation button, committed fitting IDs in result selection, and DLL/build synchronization. Post-fix checks reported 79 IFC/geometry checks and 30 WPF/result checks. Live family loading/model transactions were not tested.

## Findings before repair

1. **P1: Build failure.** PlacementCatalog assigned LoadPlacementFamily after IFCInfoWindow had lost that property. Release build failed with CS1061; UI tests could not build. Restore the callback and connect it to the placement dialog.
2. **P1: Family loading unavailable.** NativePlacementWindow was opened without sourceCategoryName/loadFamily; its default null callback hid the loading button. Restoring only the property would not restore the UI path.
3. **P2: Dedicated fitting button missing.** The footer creation button was shown only for CanCreateDucts, which CategoryReader set for Ducts. Fitting placement regressed to a generic path.
4. **P1: Published/build DLL mismatch.** At review time, outputs/IFCInfo.dll SHA256 was 50682C94486B585893345A6AF4B8735A1AC115F7DD06930561B9E8CD28B0D63B; build SHA256 was 5E2A08941878998F6936905B3BFC8796BA5E3FDE50D52E96DC1C41BC1EAF6B6C. The failing build prevented PublishLocalAddin synchronization. The release test still inspected an old dated DLL instead of the current build.
5. **P2: Result selection omitted fittings.** The callback used only the successful duct dictionary; committed fitting target IDs existed only in report rows. Selection needed combined committed duct/fitting IDs, excluding failed/rolled-back rows.

## Functional limits recorded

- Family placement uses LocationPoint or bounding-box center and the user's angle; it does not reconstruct exact IFC elbow/tee shapes, connector dimensions or full orientation. All sources in a placement run use the selected type.
- Fitting connections consider only current-run ducts, not every old network; branch splitting is unsupported.
- Source/target categories were checked in CategoryReader, PlacementCatalog and NativePlacement. At that historical checkpoint, other native builder branches were still blocked by the allowed-category list; their existence did not prove active support.
- The focused IFC reader does not support every representation. Reader tests do not replace IFC import/native geometry acceptance.
